PgBouncer Connection Pooler (Optional)

⚠️ Kapan Butuh PgBouncer?
Hanya install PgBouncer jika aplikasi Anda memiliki >1000 concurrent connections. Untuk aplikasi dengan <100 connections, gunakan client-side pooling di aplikasi (HikariCP, pg-pool, dll).

Co-locate PgBouncer dengan HAProxy

Untuk cost efficiency, install PgBouncer di server HAProxy yang sama. Setup ini cocok untuk load 1000-10000 concurrent connections.

Architecture App → PgBouncer → HAProxy → CockroachDB
Connection Reduction 5000 clients → 24 DB connections
1. Install & Configure PgBouncer SAME SERVER AS HAPROXY Pending
Install PgBouncer
bash scripts/setup_pgbouncer.sh
Saat interactive prompt:
- HAProxy IP: 127.0.0.1 (PENTING: gunakan IP, bukan 'localhost' untuk menghindari IPv6 issue)
- Port: 26257
- Password: Kosongkan jika cluster mode --insecure (Auth otomatis menjadi trust)
- Total vCPU cluster: Contoh 3 (untuk 3 nodes × 1 CPU)
- Max client connections: Disesuaikan dengan RAM server (Auto-calculated)
Verify PgBouncer Status
sudo systemctl status pgbouncer sudo netstat -tlnp | grep 6432
🛑 Troubleshooting:
Jika `netstat` hanya menampilkan 127.0.0.1:6432 (tanpa 0.0.0.0 atau :::*), jalankan restart manual:
sudo systemctl restart pgbouncer
⚠️ Troubleshooting: Jika service gagal start dengan error "No such file or directory" untuk pidfile, jalankan:
sudo mkdir -p /var/run/pgbouncer && sudo chown postgres:postgres /var/run/pgbouncer
2. Test Connection via PgBouncer VERIFICATION Pending
Connect via PgBouncer
psql -h -p 6432 -U root -d defaultdb
Monitor PgBouncer Pools
psql -h localhost -p 6432 -U root -d pgbouncer SHOW POOLS; SHOW STATS;
Update Application Connection String:
Dari: postgresql://user:pass@haproxy-ip:26257/db
Ke: postgresql://user:pass@haproxy-ip:6432/db
3. Monitor Pool Saturation ONGOING Pending
Check for Waiting Clients
psql -h localhost -p 6432 -U root -d pgbouncer -c "SHOW POOLS;"
Key Metrics:
- cl_waiting: Harus < 5 (clients menunggu connection dari pool)
- sv_active: Harus ≤ 12 (sesuai pool_size cluster vCPU 3)
- maxwait: Harus < 5s (waktu tunggu maksimal)

Jika perbandingan cl_waiting tinggi, pertimbangkan increase pool_size atau scale up CockroachDB cluster.

SQL Optimization & Monitoring

Schema Guideline: Gunakan UUID (Anti-Hotspot) Concept / Global Pending
PENTING: Jangan gunakan SERIAL (1, 2, 3...) untuk Primary Key. Hal ini menyebabkan "Hotspot" dimana semua write hanya masuk ke 1 node, membuat cluster lambat.

Gunakan UUID agar data tersebar merata ke semua node.
Contoh Schema yang BENAR
CREATE TABLE users ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), name TEXT );
Follower Reads (Scale Performance) Global Capability Pending
Stale Read Query
SELECT * FROM users AS OF SYSTEM TIME follower_read_timestamp();
Cocok untuk dashboard/history yang tidak butuh real-time 100%, mengurangi beban pada Leaseholder.
Real-time Query Monitoring ANY NODE Pending
Cek Query Lambat (>5s)
SELECT query, start, now() - start AS duration FROM crdb_internal.node_queries WHERE now() - start > '5s';

Fase Kritis: Mengamankan jaringan (Firewall) dan mengaktifkan Enkripsi (TLS) agar password authentication bisa digunakan.

1. Firewall IP Whitelisting EXECUTE ON EACH NODE Pending
Batasi Akses SQL (Port 26257) & Web UI (8080)
# Contoh UFW (Ubuntu) sudo ufw allow from 192.168.2.0/24 to any port 26257 proto tcp sudo ufw allow from 192.168.2.0/24 to any port 8080 proto tcp sudo ufw delete allow 26257/tcp
Pastikan hanya IP internal/VPN yang bisa akses port database.
2. Generate All Certificates RUN ON NODE 1 Pending
Run Automated Certificate Generator
bash scripts/generate_certs.sh
Siapkan IP Address dari Node 1, Node 2, Node 3, dan HAProxy untuk diinput ke script.
Siapkan IP Address dari Node 1 s/d Node 5, ditambah LB-A dan LB-B untuk diinput ke script (total 7 IPs).
💡 Script ini akan generate:
- CA certificate (ca.crt)
- Node certificates untuk Node 1, 2, 3 (masing-masing punya node.crt + node.key berbeda)
- Client certificate untuk root user

Masukkan IP setiap node saat diminta. Output tersimpan di ~/cockroach-certs/
3. Transfer Certificates to Each Node IMPORTANT Pending
🖥️ Node 1 (Current Node - Install Locally)
sudo mkdir -p /var/lib/cockroach/certs sudo cp ~/cockroach-certs/node1/* /var/lib/cockroach/certs/ sudo chown -R cockroach:cockroach /var/lib/cockroach/certs sudo chmod 600 /var/lib/cockroach/certs/node.key
📤 Node 2 (Transfer via SCP)
# Di Node 1, transfer files: scp ~/cockroach-certs/node2/* user@192.168.2.115:~/ # SSH ke Node 2, lalu install: ssh user@192.168.2.115 sudo mkdir -p /var/lib/cockroach/certs sudo mv ~/ca.crt ~/node.crt ~/node.key /var/lib/cockroach/certs/ sudo chown -R cockroach:cockroach /var/lib/cockroach/certs sudo chmod 600 /var/lib/cockroach/certs/node.key
📤 Node 3 (Transfer via SCP)
# Di Node 1, transfer files: scp ~/cockroach-certs/node3/* user@192.168.2.116:~/ # SSH ke Node 3, lalu install: ssh user@192.168.2.116 sudo mkdir -p /var/lib/cockroach/certs sudo mv ~/ca.crt ~/node.crt ~/node.key /var/lib/cockroach/certs/ sudo chown -R cockroach:cockroach /var/lib/cockroach/certs sudo chmod 600 /var/lib/cockroach/certs/node.key
⚠️ PENTING:
- Setiap node harus punya ca.crt yang SAMA
- Setiap node punya node.crt dan node.key yang BERBEDA (sesuai IP-nya)
- JANGAN transfer ca.key ke production servers! Simpan di tempat aman.
4. Update Systemd Service (Remove --insecure) ON ALL NODES Pending
Replace --insecure dengan --certs-dir
sudo systemctl stop cockroach sudo sed -i 's/--insecure/--certs-dir=\/var\/lib\/cockroach\/certs/g' /etc/systemd/system/cockroach.service sudo systemctl daemon-reload sudo systemctl start cockroach sudo systemctl status cockroach
Verify Secure Connection
cockroach sql --certs-dir=/var/lib/cockroach/certs --host=localhost
Jalankan command ini di semua 3 nodes. Setelah restart, cluster akan menggunakan TLS encryption untuk semua komunikasi.

Copy Client Cert to ~/.cockroach-certs
mkdir -p ~/.cockroach-certs cp ~/cockroach-certs/client/* ~/.cockroach-certs/
Test Remote Connection
cockroach sql --certs-dir=~/.cockroach-certs --host=192.168.2.114
Client certificate tersimpan di ~/cockroach-certs/client/ setelah menjalankan generate_certs.sh. Copy ke mesin yang perlu remote access.
4. Transfer CA & Node Certs MANUAL ACTION Pending
PENTING:
1. Buat cert node untuk Node 2 & 3 di Node 1 (ganti IP).
2. Transfer ca.crt dan node.crt/key ke setiap node (folder /var/lib/cockroach/certs).
3. chown -R cockroach:cockroach /var/lib/cockroach/certs
5. Restart Service in Secure Mode EXECUTE ON EACH NODE Pending
Update Systemd Service
# Hapus --insecure # Tambah --certs-dir=/var/lib/cockroach/certs sudo systemctl daemon-reload && sudo systemctl restart cockroach

PostgreSQL Migration Guide

CockroachDB kompatibel dengan PostgreSQL wire protocol. Gunakan tool MOLT untuk migrasi otomatis atau IMPORT untuk migrasi offline skala besar.

1. Install MOLT Tool SETUP Pending
Download & Install Binary (Linux AMD64)
curl -L https://molt.cockroachdb.com/molt/cli/molt-latest.linux-amd64.tgz | tar -xz sudo mv molt /usr/local/bin/ molt version
⚠️ Penting:
• Jalankan di mesin yang bisa akses PostgreSQL (5432) dan CockroachDB (26257)
• MOLT harus connect langsung ke CockroachDB (port 26257), BUKAN via PgBouncer (6432)
• Gunakan IP node CockroachDB atau HAProxy yang forward ke port 26257
2. Schema Assessment (MOLT Verify) ASSESSMENT Pending
Cek Kompatibilitas Schema
# Contoh: PostgreSQL lokal ke CockroachDB remote ./molt verify schema \ --source "postgres://postgres:password@localhost:5432/test" \ --target "postgres://root:@192.168.2.22:26257/test" # PENTING: Gunakan port 26257 (CockroachDB), BUKAN 6432 (PgBouncer)
Identifikasi perbedaan data types, triggers, atau extensions sebelum migrasi.
Troubleshooting: Jika error "failed to connect", pastikan:
• Menggunakan port 26257 (CockroachDB), bukan 6432 (PgBouncer)
• Firewall membuka port 26257
• Credentials benar (default user CockroachDB: root)
3. Data Migration (MOLT Fetch) EXECUTION Pending

Pilih Metode Transfer Data

MOLT fetch memerlukan salah satu dari 3 opsi transfer:

Opsi 1: Direct Copy (Tercepat - Recommended untuk LAN)
# Streaming langsung source → target ./molt fetch \ --source "postgres://postgres:@localhost:5432/test" \ --target "postgres://root:@192.168.2.22:26257/test" \ --direct-copy
✅ Keuntungan: Paling cepat, tidak butuh disk space tambahan
⚠️ Kekurangan: Tidak bisa resume jika gagal, butuh koneksi stabil
Opsi 2: Local Path (Paling Aman - Recommended untuk data besar)
# Export ke disk lokal, lalu import mkdir -p ~/molt-migration ./molt fetch \ --source "postgres://postgres:@localhost:5432/test" \ --target "postgres://root:@192.168.2.22:26257/test" \ --local-path ~/molt-migration
✅ Keuntungan: Bisa resume, bisa inspect data sebelum import
⚠️ Kekurangan: Butuh disk space (2x ukuran database), lebih lambat
Opsi 3: Cloud Bucket (Untuk Production/Multi-Region)
# Via Google Cloud Storage (atau S3/Azure) ./molt fetch \ --source "postgres://postgres:@localhost:5432/test" \ --target "postgres://root:@192.168.2.22:26257/test" \ --bucket-path "gs://my-bucket/molt-migration"
✅ Keuntungan: Scalable untuk TB+ data, parallel processing
⚠️ Kekurangan: Butuh setup cloud credentials, biaya storage
💡 Rekomendasi:
• Database < 10GB + LAN stabil: Gunakan --direct-copy
• Database 10-100GB atau koneksi tidak stabil: Gunakan --local-path
• Database > 100GB atau cross-region: Gunakan --bucket-path

🔴 PENTING: Langkah Sebelum MOLT Fetch

Step 1: Export & Import Schema ke CockroachDB

# Export schema dari PostgreSQL pg_dump -h localhost -U postgres -d test --schema-only -f schema.sql # Import ke CockroachDB psql "postgres://root:@192.168.2.22:26257/test" -f schema.sql

Step 2: Drop Foreign Key Constraints (Wajib!)

# Lihat FK yang ada cockroach sql --insecure --host=CRDB_IP --port=26257 --database=test -e " SELECT table_name, constraint_name FROM information_schema.table_constraints WHERE constraint_type = 'FOREIGN KEY' AND table_schema = 'public';" # Drop FK (sesuaikan dengan output di atas) cockroach sql --insecure --host=CRDB_IP --port=26257 --database=test -e " ALTER TABLE order_items DROP CONSTRAINT IF EXISTS order_items_order_id_fkey; ALTER TABLE order_items DROP CONSTRAINT IF EXISTS order_items_product_id_fkey; ALTER TABLE orders DROP CONSTRAINT IF EXISTS orders_customer_id_fkey;"

Step 3: Truncate jika ada data sisa (re-run migration)

cockroach sql --insecure --host=CRDB_IP --port=26257 --database=test -e " TRUNCATE TABLE order_items, orders, products, customers CASCADE;"

🟢 Langkah Setelah MOLT Fetch Berhasil

Re-add Foreign Key Constraints:

# Sesuaikan nama kolom dengan schema Anda cockroach sql --insecure --host=CRDB_IP --port=26257 --database=test -e " ALTER TABLE orders ADD CONSTRAINT orders_customer_id_fkey FOREIGN KEY (customer_id) REFERENCES customers(customer_id); ALTER TABLE order_items ADD CONSTRAINT order_items_order_id_fkey FOREIGN KEY (order_id) REFERENCES orders(order_id); ALTER TABLE order_items ADD CONSTRAINT order_items_product_id_fkey FOREIGN KEY (product_id) REFERENCES products(product_id);"
💡 Jika error "column does not exist", cek nama kolom PK dengan: SHOW COLUMNS FROM table_name;
4. Verify Data Consistency VERIFICATION Pending
Verifikasi Data Setelah Migrasi (Schema + Rows)
# Verifikasi lengkap (schema + data content) ./molt verify \ --source "postgres://postgres:@localhost:5432/test" \ --target "postgres://root:@192.168.2.22:26257/test"
✅ Command ini akan:
• Membandingkan schema (tabel, kolom, tipe data)
• Membandingkan jumlah rows di setiap tabel
• Membandingkan data content dengan checksum
• Melaporkan perbedaan jika ada
Opsi: Verifikasi Schema Saja (Lebih Cepat)
./molt verify \ --source "postgres://postgres:@localhost:5432/test" \ --target "postgres://root:@192.168.2.22:26257/test" \ --rows=false
Opsi: Verifikasi Tabel Tertentu
./molt verify \ --source "postgres://postgres:@localhost:5432/test" \ --target "postgres://root:@192.168.2.22:26257/test" \ --table-filter "^(users|orders)$"
💡 Best Practice:
1. Verify schema sebelum migrasi (--rows=false)
2. Jalankan molt fetch untuk migrasi data
3. Verify data setelah migrasi (default: schema + rows)
4. Simpan log untuk audit: --log-file verify-post-migration.log

Backup & Restore

Backup Strategy for Production

CockroachDB backup menggunakan BACKUP command dengan dukungan full, incremental, dan point-in-time recovery. Untuk GDPR compliance, pastikan backup retention policy sesuai regulasi.

Full Backup Snapshot lengkap database
Incremental Hanya perubahan sejak backup terakhir
Point-in-Time Restore ke timestamp tertentu
1. Full Database Backup RECOMMENDED Pending
Metode 1: Manual Backup via SQL
# Backup ke local storage node cockroach sql --insecure --host=NODE_IP --port=26257 -e " BACKUP DATABASE your_database INTO 'nodelocal://self/backups/full-$(date +%Y%m%d)' WITH revision_history;"
Metode 2: Automated Backup Script (Recommended)

Ada 3 mode restore dengan risk level berbeda:

Mode 1: Restore ke Database Baru (SAFE)

✅ Safe Mode: Data existing tetap aman, restore ke database terpisah
Mode 2: Replace Existing Database (DESTRUCTIVE)
# HATI-HATI: Ini akan menghapus database current! bash scripts/restore_cockroach.sh your_database 'nodelocal://self/backups/base-backup' replace # Script akan minta konfirmasi: ketik "YES" untuk proceed
🔴 Destructive Mode: Database existing akan di-DROP! Backup dulu sebelum replace.
Mode 3: Point-in-Time Recovery
# Restore ke waktu tertentu (butuh revision_history) bash scripts/restore_cockroach.sh your_database 'nodelocal://self/backups/base-backup' point-in-time # Script akan tanya timestamp: 2026-01-19 10:00:00
Manual Restore (Advanced)
