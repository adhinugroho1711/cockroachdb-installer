06

PgBouncer Connection Pooler (Optional)

⚠️ Kapan Butuh PgBouncer?
Hanya install PgBouncer jika aplikasi Anda memiliki >1000 concurrent connections. Untuk aplikasi dengan <100 connections, gunakan client-side pooling di aplikasi (HikariCP, pg-pool, dll).

Co-locate PgBouncer dengan HAProxy

Untuk cost efficiency, install PgBouncer di server HAProxy yang sama. Setup ini cocok untuk load 1000-10000 concurrent connections.

Architecture App → PgBouncer → HAProxy → CockroachDB
Connection Reduction 5000 clients → 24 DB connections
1. Install & Configure PgBouncer SAME SERVER AS HAPROXY Pending
Install PgBouncer
bash scripts/setup_pgbouncer.sh
Saat interactive prompt:
- HAProxy IP: 127.0.0.1 (PENTING: gunakan IP, bukan 'localhost' untuk menghindari IPv6 issue)
- Port: 26257
- Password: Kosongkan jika cluster mode --insecure (Auth otomatis menjadi trust)
- Total vCPU cluster: Contoh 3 (untuk 3 nodes × 1 CPU)
- Max client connections: Disesuaikan dengan RAM server (Auto-calculated)
Verify PgBouncer Status
sudo systemctl status pgbouncer netstat -tlnp | grep 6432
⚠️ Troubleshooting: Jika service gagal start dengan error "No such file or directory" untuk pidfile, jalankan:
sudo mkdir -p /var/run/pgbouncer && sudo chown postgres:postgres /var/run/pgbouncer
2. Test Connection via PgBouncer VERIFICATION Pending
Connect via PgBouncer
psql -h -p 6432 -U root -d defaultdb
Monitor PgBouncer Pools
psql -h localhost -p 6432 -U root -d pgbouncer SHOW POOLS; SHOW STATS;
Update Application Connection String:
Dari: postgresql://user:pass@haproxy-ip:26257/db
Ke: postgresql://user:pass@haproxy-ip:6432/db
3. Monitor Pool Saturation ONGOING Pending
Check for Waiting Clients
psql -h localhost -p 6432 -U root -d pgbouncer -c "SHOW POOLS;"
Key Metrics:
- cl_waiting: Harus < 5 (clients menunggu connection dari pool)
- sv_active: Harus ≤ 12 (sesuai pool_size cluster vCPU 3)
- maxwait: Harus < 5s (waktu tunggu maksimal)

Jika perbandingan cl_waiting tinggi, pertimbangkan increase pool_size atau scale up CockroachDB cluster.
07

SQL Optimization & Monitoring

Schema Guideline: Gunakan UUID (Anti-Hotspot) Concept / Global Pending
PENTING: Jangan gunakan SERIAL (1, 2, 3...) untuk Primary Key. Hal ini menyebabkan "Hotspot" dimana semua write hanya masuk ke 1 node, membuat cluster lambat.

Gunakan UUID agar data tersebar merata ke semua node.
Contoh Schema yang BENAR
CREATE TABLE users ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), name TEXT );
Follower Reads (Scale Performance) Global Capability Pending
Stale Read Query
SELECT * FROM users AS OF SYSTEM TIME follower_read_timestamp();
Cocok untuk dashboard/history yang tidak butuh real-time 100%, mengurangi beban pada Leaseholder.
Real-time Query Monitoring ANY NODE Pending
Cek Query Lambat (>5s)
SELECT query, start, now() - start AS duration FROM crdb_internal.node_queries WHERE now() - start > '5s';

Security Setup (Network & TLS)

Fase Kritis: Mengamankan jaringan (Firewall) dan mengaktifkan Enkripsi (TLS) agar password authentication bisa digunakan.

1. Firewall IP Whitelisting EXECUTE ON EACH NODE Pending
Batasi Akses SQL (Port 26257) & Web UI (8080)
# Contoh UFW (Ubuntu) sudo ufw allow from 192.168.2.0/24 to any port 26257 proto tcp sudo ufw allow from 192.168.2.0/24 to any port 8080 proto tcp sudo ufw delete allow 26257/tcp
Pastikan hanya IP internal/VPN yang bisa akses port database.
2. Generate All Certificates RUN ON NODE 1 Pending
Run Automated Certificate Generator
bash scripts/generate_certs.sh
💡 Script ini akan generate:
- CA certificate (ca.crt)
- Node certificates untuk Node 1, 2, 3 (masing-masing punya node.crt + node.key berbeda)
- Client certificate untuk root user

Masukkan IP setiap node saat diminta. Output tersimpan di ~/cockroach-certs/
3. Transfer Certificates to Each Node IMPORTANT Pending
🖥️ Node 1 (Current Node - Install Locally)
sudo mkdir -p /var/lib/cockroach/certs sudo cp ~/cockroach-certs/node1/* /var/lib/cockroach/certs/ sudo chown -R cockroach:cockroach /var/lib/cockroach/certs sudo chmod 600 /var/lib/cockroach/certs/node.key
📤 Node 2 (Transfer via SCP)
# Di Node 1, transfer files: scp ~/cockroach-certs/node2/* user@192.168.2.115:~/ # SSH ke Node 2, lalu install: ssh user@192.168.2.115 sudo mkdir -p /var/lib/cockroach/certs sudo mv ~/ca.crt ~/node.crt ~/node.key /var/lib/cockroach/certs/ sudo chown -R cockroach:cockroach /var/lib/cockroach/certs sudo chmod 600 /var/lib/cockroach/certs/node.key
📤 Node 3 (Transfer via SCP)
# Di Node 1, transfer files: scp ~/cockroach-certs/node3/* user@192.168.2.116:~/ # SSH ke Node 3, lalu install: ssh user@192.168.2.116 sudo mkdir -p /var/lib/cockroach/certs sudo mv ~/ca.crt ~/node.crt ~/node.key /var/lib/cockroach/certs/ sudo chown -R cockroach:cockroach /var/lib/cockroach/certs sudo chmod 600 /var/lib/cockroach/certs/node.key
⚠️ PENTING:
- Setiap node harus punya ca.crt yang SAMA
- Setiap node punya node.crt dan node.key yang BERBEDA (sesuai IP-nya)
- JANGAN transfer ca.key ke production servers! Simpan di tempat aman.
4. Update Systemd Service (Remove --insecure) ON ALL NODES Pending
Replace --insecure dengan --certs-dir
sudo systemctl stop cockroach sudo sed -i 's/--insecure/--certs-dir=\/var\/lib\/cockroach\/certs/g' /etc/systemd/system/cockroach.service sudo systemctl daemon-reload sudo systemctl start cockroach sudo systemctl status cockroach
Verify Secure Connection
cockroach sql --certs-dir=/var/lib/cockroach/certs --host=localhost
Jalankan command ini di semua 3 nodes. Setelah restart, cluster akan menggunakan TLS encryption untuk semua komunikasi.
5. Setup Client Certificate (Optional) FOR REMOTE ACCESS Pending
Copy Client Cert to ~/.cockroach-certs
mkdir -p ~/.cockroach-certs cp ~/cockroach-certs/client/* ~/.cockroach-certs/
Test Remote Connection
cockroach sql --certs-dir=~/.cockroach-certs --host=192.168.2.114
Client certificate tersimpan di ~/cockroach-certs/client/ setelah menjalankan generate_certs.sh. Copy ke mesin yang perlu remote access.
4. Transfer CA & Node Certs MANUAL ACTION Pending
PENTING:
1. Buat cert node untuk Node 2 & 3 di Node 1 (ganti IP).
2. Transfer ca.crt dan node.crt/key ke setiap node (folder /var/lib/cockroach/certs).
3. chown -R cockroach:cockroach /var/lib/cockroach/certs
5. Restart Service in Secure Mode EXECUTE ON EACH NODE Pending
Update Systemd Service
# Hapus --insecure # Tambah --certs-dir=/var/lib/cockroach/certs sudo systemctl daemon-reload && sudo systemctl restart cockroach

Security Hardening (User & Data)

Set Password Superuser (Root) GLOBAL (RUN ONCE) Pending
Set Password (Run in Terminal/Shell)
cockroach sql --certs-dir=certs --host=localhost -e "ALTER USER root WITH PASSWORD 'PasswordSuperKuat123!';"
Sekarang 'root' sudah aman dan dilindungi password.
Create Application User GLOBAL (RUN ONCE) Pending
Buat User Aplikasi (Terminal/Shell)
cockroach sql --certs-dir=certs --host=localhost -e "CREATE USER IF NOT EXISTS appuser; ALTER USER appuser PASSWORD 'AppPassword123'; GRANT ALL ON DATABASE defaultdb TO appuser;"
Enable Audit Logging GLOBAL (RUN ONCE) Pending
Aktifkan Audit Log (Terminal/Shell)
cockroach sql --certs-dir=certs --host=localhost -e "SET CLUSTER SETTING sql.log.all_statements.enabled = true;"
Connection Rate Limiting GLOBAL (RUN ONCE) Pending
Batasi Koneksi (Terminal/Shell)
cockroach sql --certs-dir=certs --host=localhost -e "SET CLUSTER SETTING server.max_connections_per_gateway = 500;"

PostgreSQL Migration Guide

CockroachDB kompatibel dengan PostgreSQL wire protocol. Gunakan tool MOLT untuk migrasi otomatis atau IMPORT untuk migrasi offline skala besar.

1. Install MOLT Tool SETUP Pending
Download & Install Binary
curl https://binaries.cockroachdb.com/molt/molt.latest.linux-amd64.tar.gz | tar -xz sudo mv molt /usr/local/bin/
Jalankan di mesin yang bisa akses PostgreSQL (5432) dan CockroachDB (26257).
2. Schema Assessment (MOLT Verify) ASSESSMENT Pending
Cek Kompatibilitas Schema
./molt verify schema \ --source "postgres://user:pass@pg-host:5432/dbname" \ --target "postgres://user:pass@crdb-host:26257/dbname"
Identifikasi perbedaan data types, triggers, atau extensions sebelum migrasi. Lihat Panduan Lengkap (Markdown).
3. Data Migration (MOLT Fetch) EXECUTION Pending
Migrasi Data Full Copy
./molt fetch \ --source "postgres://user:pass@pg-host:5432/dbname" \ --target "postgres://user:pass@crdb-host:26257/dbname"
Gunakan fetch untuk database skala kecil-menengah. Untuk skala TB, gunakan IMPORT command.
4. Verify Data Consistency VERIFICATION Pending
Bandingkan Data Source vs Target
./molt verify data \ --source "postgres://user:pass@pg-host:5432/dbname" \ --target "postgres://user:pass@crdb-host:26257/dbname"
Memastikan jumlah row dan konten data identik antara Postgres dan CockroachDB.

Multi-Site Disaster Recovery (2-Site)

🌐 Arsitektur 2+3 (Recommended): Deploy 2 nodes di Site A (Primary) dan 3 nodes di Site B (2 full + 1 witness). Witness node hanya untuk voting dengan specs minimal (1 CPU, 1GB RAM). Automatic failover saat Site A down.

Topology: 2 Site dengan Automatic Failover

Site A (Primary) Node 1, Node 2 + HAProxy
Site B (DR) Node 3, 4, 5 (Witness) + HAProxy
✅ Auto-Failover Site A down → Site B (3/5 quorum) tetap online (~5-10s downtime)
0. Provision Infrastructure (7 Servers) INFRA Pending
🏢 Site A (Primary) - 3 Servers
# CockroachDB Nodes (Full) multipass launch lts --name n1 --cpus 2 --memory 4G --disk 20G multipass launch lts --name n2 --cpus 2 --memory 4G --disk 20G # Load Balancer multipass launch lts --name lb-a --cpus 1 --memory 1G --disk 10G
🏢 Site B (DR) - 4 Servers
# CockroachDB Nodes (Full) multipass launch lts --name n3 --cpus 2 --memory 4G --disk 20G multipass launch lts --name n4 --cpus 2 --memory 4G --disk 20G # Witness Node (Lightweight - voting only) multipass launch lts --name n5 --cpus 1 --memory 1G --disk 10G # Load Balancer multipass launch lts --name lb-b --cpus 1 --memory 1G --disk 10G
📊 Total Infrastructure:
- Site A: 2 CockroachDB (full) + 1 LB = 3 servers
- Site B: 2 CockroachDB (full) + 1 Witness + 1 LB = 4 servers
- Grand Total: 7 servers
1. Deploy Nodes dengan Locality SETUP Pending
Node 1 & 2 (Site A) - Tambahkan flag --locality
--locality=site=a,rack=1 # Node 1 --locality=site=a,rack=2 # Node 2
Node 3, 4, 5 (Site B) - Tambahkan flag --locality
--locality=site=b,rack=1 # Node 3 (Full) --locality=site=b,rack=2 # Node 4 (Full) --locality=site=b,rack=3 # Node 5 (Witness - 1CPU, 1GB RAM)
Edit file /etc/systemd/system/cockroach.service dan tambahkan flag --locality pada ExecStart. Node 5 (witness) hanya untuk voting, tidak menyimpan data.
2. Set Replication Preferences CONFIG Pending
Prioritaskan Site A untuk Write Performance
ALTER DATABASE defaultdb CONFIGURE ZONE USING num_replicas = 3, constraints = '{"+site=a": 2, "+site=b": 1}', lease_preferences = '[[+site=a]]';
Penjelasan:
- num_replicas = 3: Simpan 3 copy data (dari 5 nodes)
- constraints: 2 replica di Site A, 1 di Site B (Node 3 atau 4)
- lease_preferences: Leaseholder (write coordinator) prefer Site A
- Node 5 (witness): Hanya untuk voting, tidak menyimpan data
2a. Setup Load Balancers (Both Sites) LB Pending
🏢 Site A: LB-A (Primary) - Prioritas Local Nodes
# On lb-a server bash scripts/setup_loadbalancer_os.sh bash scripts/setup_haproxy.sh # Saat interactive prompt: # - Node IPs: ,,, # - Prioritas: Node 1, 2 (local) sebagai primary # - Node 3, 4 (remote) sebagai backup
🏢 Site B: LB-B (Standby) - Prioritas Local Nodes
# On lb-b server bash scripts/setup_loadbalancer_os.sh bash scripts/setup_haproxy.sh # Saat interactive prompt: # - Node IPs: ,,,, # - Prioritas: Node 3, 4, 5 (local) sebagai primary # - Node 1, 2 (remote) sebagai backup
🔄 Application Connection:
- Primary: lb-a:26257 (Site A)
- Failover: lb-b:26257 (Site B)
- Best: lb-a:26257,lb-b:26257 (multi-host)
3. Runbook: Site A Down Total EMERGENCY Pending
Step 1: Verify Cluster Status (Automatic Failover)
cockroach node status \ --certs-dir=/var/lib/cockroach/certs \ --host=
Step 2: Update Application Connection String
# Dari: haproxy-site-a:26257 # Ke: haproxy-site-b:26257
✅ Automatic Failover: Cluster tetap online dengan 3/5 quorum (Node 3, 4, 5). Downtime hanya ~5-10 detik untuk HAProxy detect node down. Tidak perlu manual intervention!
4. Runbook: Site A Recovery (Rejoin) RECOVERY Pending
Step 1: Wipe Old Data (Node 1 & 2)
sudo systemctl stop cockroach sudo rm -rf /var/lib/cockroach/cockroach-data/* # JANGAN hapus /var/lib/cockroach/certs/
Step 2: Rejoin Node 1 & 2 ke Cluster
cockroach start \ --certs-dir=/var/lib/cockroach/certs \ --advertise-addr= \ --join=,, \ --locality=site=a,rack=1
Step 3: Restore Replication Preferences
ALTER DATABASE defaultdb CONFIGURE ZONE USING num_replicas = 3, constraints = '{"+site=a": 2, "+site=b": 1}', lease_preferences = '[[+site=a]]';
✅ Zero Downtime: Recovery dilakukan saat cluster sudah online di Site B. Node 1 & 2 akan mendapat ID baru (misal: Node 6 & 7). Node 5 (witness) tetap ada dan tidak perlu di-decommission.
5. Test Failover (Controlled) TESTING Pending
Test 1: Single Node Failure
sudo systemctl stop cockroach # Di Node 1 # Cluster harus tetap online (4/5 quorum) cockroach sql --certs-dir=/var/lib/cockroach/certs --host= -e "SELECT 1;"
Test 2: Complete Site A Failover (Automatic)
# Stop Site A sudo systemctl stop cockroach # Node 1 sudo systemctl stop cockroach # Node 2 # Wait 5-10 seconds - cluster should auto-failover # Verify cluster online from Site B cockroach sql --certs-dir=/var/lib/cockroach/certs --host= -e "SELECT 1;" # Check node status cockroach node status --certs-dir=/var/lib/cockroach/certs --host=
📊 Expected Results:
- Test 1: Auto-failover dalam ~5-10 detik (4/5 quorum)
- Test 2: Automatic failover dalam ~5-10 detik (3/5 quorum), zero manual intervention
